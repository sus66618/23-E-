# 运动目标控制与自动追踪系统｜双树莓派视觉上位机

本项目是 2025 年大连理工大学电子设计竞赛校赛一等奖作品，赛题采用 2023 年全国大学生电子设计竞赛 E 题《运动目标控制与自动追踪系统》原题。

系统由红色运动目标控制系统和绿色自动追踪系统组成。两套装置按照赛题要求完全独立、互不通信，分别使用 Raspberry Pi 5 完成视觉处理，并通过 USB-TTL 串口向各自的 RoboMaster C 型开发板发送位置偏差，由下位机控制二维舵机云台和激光笔运动。

> 本仓库公开的是两套 Raspberry Pi **视觉上位机**代码。本人在团队中独立完成视觉算法、上位机代码及现场调试；单片机程序、串口协议与云台执行机构由队友负责。

## 系统任务

原题要求搭建两套相互独立的激光控制系统：

1. 红色系统控制红色光斑复位，并沿屏幕边线或任意位置、任意角度放置的黑色胶带矩形巡航。
2. 绿色系统仅通过自身摄像头观察屏幕，自动追踪红色光斑。
3. 两套系统之间禁止任何形式的通信，不能使用台式机或笔记本电脑参与现场运行。

因此，本项目没有把红色系统的目标坐标直接发送给绿色系统。绿色系统必须从自己的画面中同时识别红、绿光斑，再独立计算追踪偏差。

## 系统架构

```text
红色目标控制系统（独立）
USB 摄像头 → Raspberry Pi 5 → 黑框/红点识别 → 路径规划
                                      ↓ USB-TTL
                             RoboMaster C 型开发板
                                      ↓
                                二维云台 + 红色激光

绿色自动追踪系统（独立）
高速 USB 摄像头 → Raspberry Pi 5 → 红/绿光点识别 → 偏差计算
                                         ↓ USB-TTL
                                RoboMaster C 型开发板
                                         ↓
                                   二维云台 + 绿色激光

       两套系统之间无数据连接，仅通过屏幕上的光斑形成视觉闭环
```

## 软件与算法

### 1. 黑色胶带边框检测

红色系统将相机图像转换到 HSV 色彩空间，通过阈值分割提取黑色区域，再使用形态学操作抑制噪声。随后利用轮廓检测、多边形逼近、面积及四边形条件筛选黑框的内外轮廓。

由于 OpenCV 返回的角点顺序不固定，程序计算角点相对几何中心的极角，并将两组四边形统一整理为左上、右上、右下、左下的对应顺序。内外轮廓对应角点取中点后，得到位于胶带中心线上的四个巡航顶点。

### 2. 红色光斑识别

红色在 HSV 色相环两端分布，因此程序使用两段阈值分别生成掩码，再合并结果。经过高斯滤波和形态学闭运算后，通过外部轮廓及最小外接圆估计光斑中心。

### 3. 矩形中线插值巡航

若直接把下一个矩形顶点作为控制目标，云台容易因目标跨度过大而冲过角点，造成红色光斑脱离胶带。程序将相邻巡航顶点之间的线段离散为一系列小步长插值点：

1. 按顺序选择当前边的起点和终点；
2. 根据线段长度生成等间距目标点；
3. 红点到达当前目标点的阈值范围后，切换到下一个插值点；
4. 到达顶点后进入下一条边，循环完成矩形巡航；
5. 对每次输出设置最大步长，减小突变并提高云台控制稳定性。

这里的目标点编号在程序中使用 `0–3`，分别对应排序后的四个矩形中线顶点。

### 4. 绿色光斑追踪

绿色系统从同一帧图像中分别提取红色和绿色光斑，计算二者的像素坐标差：

```text
dx = red_x - green_x
dy = red_y - green_y
```

偏差经比例缩放后通过串口发送给绿色系统下位机，由云台驱动绿色光斑逼近红色光斑。是否进入题目规定的追踪范围，也根据两光斑的像素距离进行判断。

## 两个最主要的现场难点

### 光斑跨越白墙与黑色胶带时亮度突变

激光笔功率保持不变，但白色背景和黑色胶带对光线的反射、吸收特性差异明显。同一个光斑落在两种表面时，亮度和颜色表现会显著变化，固定但未经现场校准的 HSV 阈值很容易漏检。

解决方法是在实际装置、光照和摄像头条件下反复采样调参，分别观察光斑位于白墙、胶带及边缘位置时的 HSV 分布，再配合形态学处理确定兼顾两种背景的阈值范围。

### 红点在窄胶带上的稳定自主巡航

仅依次追逐四个顶点会产生大跨度控制指令，红点容易冲过角点或在转向时离开胶带。最终方案不直接追逐远端顶点，而是在相邻顶点之间建立点到点路径并进行密集线性插值，使每次目标更新保持较小步长；到达一个顶点后，再连续切换至下一条边。

这套方法将“绕矩形运动”转化为连续的小目标点跟踪问题，降低了上位机输出突变对下位机闭环和机械云台的冲击。

## 串口接口

串口通信协议由团队中的下位机成员设计，本仓库仅按协议封装并发送视觉偏差。

红色系统发送 5 字节数据包：

```text
[x_high, x_low, y_high, y_low, checksum]
```

绿色系统在此基础上增加 1 字节状态标志：

```text
[x_high, x_low, y_high, y_low, checksum, flag]
```

坐标以有符号 16 位整数拆分为高、低字节。修改协议前必须与对应下位机程序同步，不能只改上位机一侧。

## 运行环境

- Raspberry Pi OS
- Python 3
- OpenCV
- NumPy
- pySerial

> 代码保留了比赛调试完成时的串口配置，两个脚本当前均写为 `COM7`。部署到 Raspberry Pi 时，需要将其改为现场 USB-TTL 对应的设备路径（通常类似 `/dev/ttyUSB0`）；这只是串口设备名差异，不改变视觉算法和通信数据包。

安装 Python 依赖：

```bash
python3 -m pip install -r requirements.txt
```

在 Raspberry Pi 上运行前，需要确认：

1. 摄像头编号与 `cv.VideoCapture(0)` 一致；
2. 将代码中的 `COM7` 修改为实际 USB-TTL 设备名称，Linux 下通常类似 `/dev/ttyUSB0`；
3. 当前用户拥有摄像头和串口访问权限；
4. HSV 阈值应在实际光照、背景和摄像头条件下重新标定；
5. 下位机固件与本仓库使用的串口数据包格式一致。

分别启动两套上位机：

```bash
python3 light_track_red.py
python3 light_track_green.py
```

两份程序应运行在各自独立的 Raspberry Pi 上，而不是在同一设备内交换数据。按 `q` 退出程序。

## 参数说明

红色巡航主要参数位于 `light_track_red.py` 顶部：

| 参数 | 含义 |
| --- | --- |
| `arrival_threshold` | 判定光斑到达当前插值点的像素阈值 |
| `interp_step_size` | 相邻插值目标点的间距 |
| `max_step` | 单次输出的最大步长 |
| `scale` | 输出偏差的比例缩放 |

绿色追踪主要使用 `scale`、`max_dis` 和 `max_step` 调节追踪响应与接近判定。参数具有装置相关性，更换摄像头、云台位置或现场光照后应重新测试。

## 安全提示

- 调试激光设备时避免光束照射眼睛、人员或高反射表面。
- 上电前限制云台活动范围，确认急停和断电方式可用。
- 单独调试视觉程序时可以暂时关闭串口发送，避免错误目标造成云台突然运动。
